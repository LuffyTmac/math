## 退出登录 404 修复

用户反馈点击退出登录出现 Whitelabel 404。根因：Spring Security 的 logout 默认只接受 POST（防 CSRF），而 index.html 的退出用的是 `<a th:href="@{/logout}">` 超链接（GET），GET /logout 无映射故 404。修复：将退出改为 `<form th:action="@{/logout}" method="post">` 表单提交，Thymeleaf 的 th:action 会自动注入 _csrf 隐藏域（与登录表单同机制）。退出成功后按 SecurityConfig 配置重定向到 /login?logout，登录页显示"已安全退出"。SecurityConfig 的 logout 配置无需改动。模板改动因 thymeleaf.cache=false 即时生效，无需重启。

## 禁用 MyBatis-Plus DdlApplicationRunner

- 用户要求禁用 MyBatis-Plus 启动时的 DdlApplicationRunner（自动 DDL 维护）。
- **定位**：反编译 mybatis-plus-spring-boot-autoconfigure-3.5.5.jar，DdlApplicationRunner 由 MybatisPlusAutoConfiguration 的 @Bean 方法 ddlApplicationRunner(List<IDdl>) 注册，带 @ConditionalOnMissingBean（无 @ConditionalOnProperty 配置项可关，也不能 exclude 整个 MybatisPlusAutoConfiguration 否则丢失 SqlSessionFactory）。
- **禁用方式**：在 MybatisPlusConfig 里加一个 @Bean DdlApplicationRunner，返回匿名子类（new DdlApplicationRunner(emptyList)），覆盖 run 为空操作。因 @ConditionalOnMissingBean(DdlApplicationRunner.class) 看到已有同类型 Bean，自动配置不再创建原实例；自定义 Bean 的 run 空操作 → 彻底禁用。DdlApplicationRunner 非 final、run 非 final，可继承覆盖。
- 编译 BUILD SUCCESS（10 源文件）。Java 改动需重启应用生效。后续若要恢复自动 DDL，删除该 @Bean 即可。

## 提示展示条件优化：未答题前隐藏提示

- **需求**：用户答题时，如果还没答过此题，即使题目设置了 hintVisible=1（展示提示），也要隐藏提示；只有用户答过此题 且 hintVisible=1 时才展示。
- **BountyController.answerForm**：显式计算 hasAnswered 标志并传给模板。原代码已经会重定向已答过的用户，所以此分支恒为 false，但保留逻辑使判断条件明确。
